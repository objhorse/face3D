# 三视角几何优化指标重设计

日期：2026-07-14
分支：`codex/restore-7-12-full`
基线：方案 C v2（`captures_20260612_140210_silhouette_c_v2`）

## 1. 背景与目标

方案 C v2 的直观脸型优于基线，并且三个视角的可信轮廓均有改善，但报告中的部分像素误差反而升高。根因不是 v2 必然更差，而是旧指标混合了三类含义不同的观测：

1. 检测器 `0-16` 点描述当前视角的最外轮廓，并不对应跨视角固定的三维皮肤点。
2. 侧视图的照片 mask 包含皮肤分割语义，而 FLAME 渲染的是完整头部表面，两者边界并不处处等价。
3. 内部五官关键点适合限制位置漂移，但不能完整表达脸颊、下颌和鼻部三维形状。

本设计只重构几何优化的评价和接受规则，不改变三相机采集条件、不引入纹理相似度，也不增加自由顶点残差。

目标是让优化器回答一个明确问题：候选模型是否在三个相机视角下更符合可相信的真实脸部轮廓，同时没有破坏五官位置和网格质量。

## 2. 方案选择

采用“可信轮廓主指标 + 区域重合辅助指标 + 内部五官保护门禁”。

不采用单一全 mask 像素误差作为主指标，因为侧脸的头发、耳朵、远侧脸缘和颈部会造成语义不一致。不采用渲染图像或人脸 embedding 相似度，因为当前纹理仍有错位和拼接痕迹，会把纹理问题错误地归因于几何。

旧 `0-16` 固定轮廓误差继续输出，名称明确标记为 legacy diagnostic，但不进入优化 loss、候选排序或接受门禁。

## 3. 指标分层

### 3.1 主指标：可信轮廓距离

每个视角自动生成可信轮廓带：

- 正面：左右脸颊外缘、下颌和下巴；排除发际线、耳朵和颈部。
- 左侧与右侧：只使用靠近相机的可见面部 profile，包括额头下段、鼻梁、鼻尖、嘴唇前缘、下巴和近侧下颌；远侧脸缘低权或排除。
- 断裂、低置信或落在头发/背景附近的目标边界不参与评分。

距离采用双向但非对称的轮廓距离：

- 目标到模型：要求真实可信轮廓附近存在模型轮廓。
- 模型到目标：只在可信带内计算，防止完整头部轮廓被皮肤 mask 的缺失区域误罚。

所有距离除以该视角的人脸框宽度，报告单位为 `% face width`。原始像素值仍可输出用于调试，但不作为跨数据集门槛。

三视角聚合使用视角等权平均，同时保留每个视角独立结果，防止正面改善掩盖某个侧面恶化。

### 3.2 辅助指标：可信区域重合

在可信脸部区域内计算 weighted IoU/Dice，只覆盖脸颊、下颌和下巴等 mask 语义相对稳定的区域。该指标用于发现轮廓距离未覆盖的大面积偏差，但权重低于可信轮廓距离。

头发、耳朵、颈部、远侧遮挡区和低置信分割区权重为零。辅助指标不能单独决定接受候选。

### 3.3 保护指标：内部五官投影

眼睛、鼻部、嘴部的内部关键点 `17-67` 继续作为保护锚点，不再与轮廓主指标混成一个总分。

候选允许内部关键点小幅上升，因为 FLAME shape 的整体脸型改善可能带来有限联动；但三视角平均恶化不得超过 `0.15% face width`，任一视角不得超过 `0.25% face width`。以常见的 1000 px 脸宽为例，这分别约为 1.5 px 和 2.5 px。报告同时显示像素值，便于人工理解。

鼻翼等已知检测器与 FLAME 定义不一致的点单独列为语义诊断，不允许它们独自否决候选。后续若有可靠的鼻边界观测，应进入鼻部专用几何指标，而不是恢复固定点硬拉。

### 3.4 几何质量门禁

以下为硬门禁，任一失败都拒绝候选：

- 顶点和面片索引无 NaN/Inf。
- 面数不下降，拓扑连接不改变。
- 不新增退化面、非流形边或异常边界。
- shape 参数和相对基线的 shape delta 有限且不超过配置上限。
- 不启用自由顶点残差或深度顶点置换。

## 4. 候选接受规则

候选必须同时满足：

1. 三视角可信轮廓归一化均值明确改善，最小改善量默认为 `0.10% face width`。
2. 至少一个视角产生超过测量分辨率的明确改善；至少两个视角改善或保持在测量不确定区间内。每个视角的不确定区间取 `0.15% face width` 与该视角一个轮廓渲染像素对应比例中的较大值。
3. 可信区域 IoU/Dice 不发生显著下降，容许波动上限为 `0.5` 个百分点。
4. 内部五官保护指标满足第 3.3 节限制。
5. 所有几何质量硬门禁通过。

这些条件分别报告，不合成为一个加权总分。这样可以直接说明候选因为什么被接受或拒绝，也避免调节一个权重后偷偷牺牲另一类质量。

若候选失败，pipeline 保留 baseline 几何和纹理，不覆盖 `face.glb`，并在报告中列出具体失败项。

## 5. 模块与数据流

扩展 `src/geometry/differentiable_silhouette.py`，将职责拆成可独立测试的四部分：

1. `build_trusted_contour_regions`：根据视角、脸框和 shape mask 生成可信轮廓带及区域权重。
2. `trusted_contour_metrics`：计算归一化双向轮廓距离和每视角结果。
3. `trusted_region_overlap_metrics`：计算可信区域 weighted IoU/Dice。
4. `evaluate_geometry_candidate`：读取主指标、保护指标和 mesh quality，返回结构化接受决定与失败原因。

优化数据流为：三视角预处理结果 -> 可信区域生成 -> baseline 指标 -> shape 优化 -> candidate 指标 -> 多门禁判定 -> 接受 candidate 或回退 baseline。

优化 loss 与验收指标使用同一套可信区域定义，但验收在优化结束后独立重算，避免直接相信训练过程中的缓存值。

## 6. 报告行为

质量报告将几何与纹理分为独立章节。几何章节按视角展示：

- 原图与模型纯几何轮廓叠加。
- 参与主指标的可信轮廓以高亮显示，被排除区域以灰色显示。
- baseline/candidate 的 `% face width` 轮廓距离。
- 可信区域 IoU/Dice。
- 内部五官保护误差及允许上限。
- legacy `0-16` 误差，明确标记“不参与优化和验收”。

报告顶部不再显示含义混杂的单一“总误差”，改为 `accepted/rejected`、三视角轮廓变化、五官保护结果和网格质量四项摘要。

## 7. 错误与降级

- 某视角无法生成足够可信的轮廓：该视角标记 invalid；不足两个有效视角时跳过 shape refinement 并保留 baseline。
- mask 为空、断裂严重或脸框异常：拒绝进入指标计算，记录输入质量问题。
- 距离变换、光栅化或指标出现 NaN/Inf：拒绝候选并保留 baseline。
- CUDA/nvdiffrast 不可用：保持当前明确失败行为，不静默切换到含义不同的旧轮廓优化。
- 报告生成失败不能改变已经完成的几何判定，但 pipeline 必须记录报告错误。

## 8. 测试与验收

单元测试：

- 同一轮廓在不同图像分辨率下得到近似相同的 `% face width` 误差。
- 小于一个轮廓渲染像素的变化被标记为保持，而不是被误判为明确改善或恶化。
- 侧视图远侧边界、头发、耳朵和颈部不影响主指标。
- 正面左右脸颊和下巴均进入可信区域。
- 候选改善两个视角但严重破坏第三视角时被拒绝。
- 内部五官超过保护阈值时被拒绝。
- legacy `0-16` 数值变化不影响接受决定。
- mesh quality 任一硬门禁失败时拒绝候选。

数据集验收使用 `captures_20260612_140210`：

- 重新评价 baseline 与方案 C v2，确认 v2 的直观改善能由可信轮廓指标解释。
- 完整 pipeline 生成带纹理 GLB、纯几何诊断和新版质量报告。
- 新报告不再因侧视图完整头部与皮肤 mask 语义不同而显示 70 px 级误导性主误差。
- v2 或后续候选必须保持 159,616 个面、零新增退化面和零新增非流形问题。
- 最终仍由 baseline/candidate viewer 做视觉复核；指标负责筛掉明确错误候选，不宣称替代人的相似度判断。

## 9. 范围边界

本阶段解决“如何正确指导和评价三视角整体脸型优化”。它不直接解决纹理拼接、鼻孔贴图错位、FLAME 表达能力上限或医疗级测量问题。纹理修复必须使用独立指标和实验，不得重新混入几何接受规则。
